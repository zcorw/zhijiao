# 交往记录人物关联可选

沿用原交往记录栏目。「记一笔」与通用交往编辑器均允许不选择人物；只填写事件或感受正文即可保存，标题留空时使用正文首行（最多 300 个字符）。也支持只填标题。两者皆为空时阻止提交。无人物记录是完整记录，不建立占位人物，也不增加草稿或待整理状态。

首页近期交往与全部交往都包含无人物记录，继续按发生时间、发生日期或未填日期时的创建时间倒序排列。全部交往可搜索标题、正文、日期与关联人物。人物时间线仅显示参与者数组包含该人物的交往。编辑可补关联、逐个取消，或使用「取消全部关联」清空参与者；记录正文和版本历史均保留。取消选择器不提交人物草稿。

「我的感受与印象」附加条目仍表示针对具体人物的独立印象，约定和计划也沿用原有人物要求。只记自己的当时感受，直接写入交往正文即可，无需添加附加条目。删除人物的既有确认和级联删除语义未改；解除交往关联只更新交往，不调用删除。

## 数据兼容与边界

`Interaction.participantIds` 已是字符串数组，本次仅移除客户端实体校验的至少一人限制，保留数组必填、UUID、去重、上限与有效引用校验。旧有关联人物记录的数据结构完全不变。服务端保存认证密文 envelope，没有交往人物列或外键，因此无 SQL 迁移、格式版本或同步协议变更。

AES-GCM、IndexedDB 原子 outbox、服务端 CAS/幂等同步、不可变历史、恢复及加密备份流程未改。已有记录无需重写。旧版客户端的非空校验不识别新产生的空关联记录；多设备使用本功能前需载入更新后的客户端。

保留工作区原有的 13 个日期／日期时间入口统一组件及交互修复，范围见 [日期输入说明](all-date-inputs.md)。本轮仅提交功能源码、测试和必要文档，不包含本地配置、密钥、数据、数据库、工具缓存或临时产物；不部署 VPS 或发布镜像。

- `npx.cmd vitest run --configLoader runner`：8 文件、60 项通过。新增结构约束及虚构 IndexedDB 生命周期覆盖离线创建、刷新读取、编辑、补关联、解除关联、同步至另一设备、6 个版本历史及恢复、加密备份导入和既有关联交往回归。
- `npm.cmd run typecheck`、`npm.cmd run lint`、`npm.cmd run build`：通过。构建保留第三方注释和大包体的非致命提示。
- 隔离 PostgreSQL 集成：17/17 通过；专项浏览器测试：2/2 通过。覆盖桌面与手机无人物创建、只填正文、刷新解锁、编辑、补关联、逐个解除与全部解除、日期和内容搜索、人物时间线、历史恢复与第二浏览器同步。
- 完整浏览器回归：12/12 通过（48.1 秒），包括原加密 CRUD、离线、头像、表单与全部日期入口测试。专项 2/2 单独运行亦通过（17.9 秒）；PostgreSQL 17/17 用时 14.70 秒。

测试使用本次全新嵌入式 PostgreSQL 集群和独立虚构账号，应用与集成测试分别使用专用数据库。完整浏览器测试复用同一虚构账号时，在专用测试库重置其登录限流计数；生产限流规则没有改动，限流安全测试在另一集成库正常验证。修复了测试将新交往必然视为首页最近五条的假设，改为在全部交往中严格验证重复保存仅生成一条；专项仍检查适用记录出现在首页。

本机实际命令为 `node .tools/run-optional-integration.mjs`、`node .tools/run-optional-e2e.mjs`；`.tools` 仅含忽略的测试辅助文件。干净检出按 README 准备可丢弃虚构实例、专用 `TEST_DATABASE_URL` 与显式 `E2E_BASE_URL` 后，可运行 `npm run test:integration` 和 `npx playwright test`。
