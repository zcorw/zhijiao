# 议题与思考

人物页保留对具体人物的感受与印象；议题页记录对问题的理解。两种记录分开存储和展示，标签仅用于分类，不充当议题身份。

## 使用方式

- 议题包含稳定 ID、名称和可选说明。重命名不会改变已有思考的归属。
- 议题详情按思考形成时间显示时间线，并列出每条思考的来源交往。来源交往的发生日期单独显示。
- 交往详情提供“添加人物感受”和“添加议题思考”，自动关联当前交往。人物感受仍需明确评价对象；议题思考无需评价人物，可以选择已有议题或在保存时一并新建议题。
- 两类记录均可编辑标题、正文、内容性质、主题标签、形成时间、多条交往依据及可选引用。引用明确标注原话或转述，并单独指定表达者；参与交往不代表赞同观点，也不自动成为评价对象。记录作者为当前资料库所有者。
- 来源要求沿用原感受表单规则：保存时至少关联一条具体交往，可添加多条并分别说明产生、支持、反证或促使修正。同一交往不重复添加。无人物交往仍可独立保存及作为来源。
- 修正表述使用编辑及版本历史；认识变化通过“追加新思考”创建另一条记录并关联旧思考。同一人物或议题的修订链不得跨对象或循环。
- 人物页只通过实际参与的交往追溯相关议题，思考不会混入该人物的感受列表。

手机底部固定为首页、人物、交往、议题、事项五栏，设置位于顶部并保留文字入口。桌面继续使用侧栏，包含独立设置入口。

## 数据与兼容

新增 `topic` 和 `thought` 两种客户端业务实体，复用原 `records` 密文路由。`reflection` 保留原人物含义和必填 `personId`，增加可选内容字段；旧记录不会通过正文、参与者或人物数量猜测归类。旧链接省略 `targetKind` 时仍指向人物感受；思考链接明确携带 `targetKind: 'thought'`。

议题、思考、标签、引用及关系均在本机解锁后使用，同步与 IndexedDB 继续只保存认证密文。未新增服务端明文索引、AI 服务或向模型发送思考的路径。现有交往解析继续只消费用户显式确认的交往内容。

没有数据库结构迁移，也没有批量改写旧记录。旧版可能留下已删除前序或循环的感受关联；新版保留这些已有表述，不会猜测修复，未改变的旧关联不会阻塞密钥轮换。新建或变更的关联及议题思考继续严格校验。新代码可读取旧备份；新版备份仍包含完整密文版本、来源链接和密钥包，并通过既有预览、完整性验证和空本机库导入流程恢复。保留版本历史，恢复旧版是生成新 revision。单条历史恢复只恢复选中的实体；来源链接有各自历史，不自动回滚整次编辑的来源集合。完整备份包含这些独立版本。旧客户端的严格模型校验不认识新增实体，因此开始写入议题后，应先升级所有使用该资料库的客户端；代码回退需同时恢复升级前备份到隔离环境，不能假定旧客户端可读取新版数据。

## 删除与恢复

含思考的议题不可直接删除，避免留下无归属思考。已有后续认识的感受或思考需先处理后续记录再删除；删除思考会删除其当前交往链接，但保留历史；删除标签从当前记录移除该分类。删除被引用人物保留思考、引用称呼以及作为思考来源的交往，必要时将交往参与者清空，不把思考当成人物私有记录删除。删除来源交往只删除来源关联及相应当前引用来源标识，不删除思考正文。

需要恢复已删除依赖时，先在设置中的已删除记录恢复依赖，再恢复思考或链接。备份恢复遵循原有资料库 ID、所有者和空目标校验，不自动跨账号导入。

## 本地验收

使用独立临时 PostgreSQL 数据库和虚构账号，不读取或改动生产资料；AI 提供者未配置。独立分支仅包含议题功能相关的 21 个文件，原有交往解析修改未并入。拆分后在隔离目录重新通过 168 项单元测试、21 项真实 PostgreSQL/HTTP 集成测试、20 项桌面/手机浏览器回归（包含 3 项议题流程），测试依赖与服务端、前端均来自隔离目录。全量类型检查、Lint、构建及 diff 检查通过。隔离验证的日志和合成数据截图保留在本机 `.local/topics-publish/evidence/`，不包含在本次提交中。单元用例覆盖旧记录读取、多来源增删、改名、引用归属、人物删除、历史与备份，浏览器用例覆盖分开的两个入口、直接新建议题、取消、返回、连续点击以及手机五栏与顶部设置。
