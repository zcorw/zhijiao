# 表单验证

使用固定版本 **vee-validate 4.15.1** 的 `useForm` / `useField`，与当前 Vue 3.5 兼容。它不附带 UI，因此保留知交原有米白和绿色布局。采用稳定的 v4；没有引入 v5 beta、整套组件库或需要 Zod 3 的适配包。

依据：[官方组合式表单 API](https://vee-validate.logaretm.com/v4/api/use-form/)、[验证行为说明](https://vee-validate.logaretm.com/v4/guide/components/validation/)。字段使用中文函数规则；部分日期仍由共享 schema 检查日历合法性。服务端及加密业务层的检查继续保留。

## 行为约定

- 首次展示保持安静；字段失焦后显示该字段错误。提交时检查全部当前字段、展开错误所在的折叠区域并聚焦首个错误。
- 字段有可见标签、`aria-required`、`aria-invalid`、关联的错误描述和文本图标；错误不只依靠颜色区分。表单使用 `novalidate`，停止浏览器默认气泡。
- 已触发验证的字段在纠错时更新提示。日期时间控件的 `badInput` 也转换为中文提示。收起的可选事项、移除的感受和切换模式后的隐藏字段从当前验证中注销。
- 使用表单提交状态和业务忙碌状态防止重复提交；服务端错误保留。提交处理结束后重置校验状态，避免主动清空密码/口令产生虚假的必填错误。
- 取消或锁定时销毁表单，释放表单值、明文和口令引用。浏览器无法保证物理内存擦除；此处没有改变底层加密和锁定机制。

## 验证范围

登录、首次建立资料库、解锁、人物和关联记录编辑、一次提交交往及可选感受/事项、修改解锁口令、数据密钥更换确认、加密备份验证。快速选择器的搜索不是提交表单，仍沿用原交互。

新增 `tests/unit/form-validation.test.ts` 检查空白字符、长度、日期、恢复秘密格式、密码不被修剪以及必要选择/确认。`tests/e2e/form-validation.spec.ts` 检查失焦/提交时机、错误焦点、纠错、服务端错误、重复点击、动态字段、取消、锁定和手机缩短视口后的按钮位置；既有 CRUD、离线及头像浏览器测试同时回归。

本轮使用独立 Compose 项目 `zhijiao-form-check`、独立数据库和回环端口 3328，所有资料均为虚构。反复测试可重置该专用测试库的登录尝试计数；账号、会话策略、限流配置及用户当前实例保持不变。自动 trace 和失败截图关闭，只手动保存不含秘密的错误状态。手机检查为 Chromium 视口模拟，尚未在 iOS/Android 实机上验证。
